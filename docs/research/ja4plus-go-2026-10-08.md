## 3 JA4 规则（原文可照抄比对）

出处：图像转写页 `docs/specs/foxio/JA4.md`、逐字转录页 `docs/specs/foxio/deleted-text-specifications.md:101-257`（读自 FoxIO `7ff7b327` 的 `technical_details/JA4.md`，下称 dts）、方法页 `docs/methods/ja4.md`、代码。

**版本 token**
- dts:137 `If extension 0x002b exists (supported_versions), then the version is the highest value in the extension. Remember to ignore GREASE values. If the extension doesn’t exist, then the TLS version is the value of the Protocol Version. Handshake version (located at the top of the packet) should be ignored.`
- dts:139-147 表：`0x0304=“13” 0x0303=“12” 0x0302=“11” 0x0301=“10” 0x0300=“s3” 0x0200=“s2” 0x0100=“s1” Unknown=“00”`。
- 代码表 `internal/parser/tls.go:345-368`：上述除 `0x0100`，另加 `0xfeff→d1 0xfefd→d2 0xfefc→d3`，default `00`。**即本实现给 SSL 1.0 写 `00` 而非 `s1`**，与 dts:145 不一致（JA4.md:64-66 称表有九值）。最高非 GREASE 逻辑 `ja4.go:359-372`。
- 协议字母 `ja4.go:351-358`：`t`/`q`/`d`；`d` 只见于文本规范（JA4.md:53-59）。**JA4.md:261-268 的 Reading 段：pin 处各参考实现都按承载 hello 的传输层判 `q`**，并记录某实现历史上曾按扩展 57 判定、该写法在 pin 处已不存在。

**SNI 位**
- dts:150 `If the SNI extension (0x0000) exists, then the destination of the connection is a domain, or “d” in the fingerprint. If the SNI does not exist, then the destination is an IP address, or “i”.`
- 代码 `ja4.go:374-379`（`sniChar := "i"`，`ch.HasSNI` 则 `d`）；`HasSNI` 仅由扩展 0 出现置位（tls.go:213-215），与名字是 IP、为空或不可解析无关（tls.go:434-455）。**上游无 IP 型 SNI 的第三字母，也无"空 SNI 记 i"的规则。**

**计数**
- dts:153 `2 character number of cipher suites … If there’s > 99, which there should never be, then output “99”. Remember, ignore GREASE values. They don’t count.`
- dts:156 `Same as counting ciphers. Ignore GREASE. Include SNI and ALPN.`
- 代码 `ja4.go:380-390`：两计数均 GREASE 过滤后 `>99→99`，`%02d`。**全文无 999/0xff 溢出编码**；扩展计数**含** SNI/ALPN。GREASE 判定 `internal/parser/grease.go:4-6`：`(value&0x0F0F)==0x0A0A && (value>>8)==(value&0xFF)`。

**扩展列表（part c 输入）**
- dts:182 `A 12 character truncated sha256 hash of the list of extensions, sorted by hex value, followed by the list of signature algorithms, in the order that they appear (not sorted).`
- dts:184 `…lower case, comma delimited, sorted (not in the order they appear). Ignore the SNI extension (0000) and the ALPN extension (0010) as we’ve already captured them in the _a_ section of the fingerprint.`
- **排除集合只有 0x0000 与 0x0010**（`ja4.go:416-431` 仅比较 `ExtSNI/ExtALPN`，常量 tls.go:21-22）。pre_shared_key(41)、renegotiation_info(11)、early_data、quic_transport_parameters(57)、application_settings(ff01) 全保留；dts:186-198 示例排序后仍含 `4469`、`ff01`，并注 `(notice 0000 and 0010 is removed)`。
- 排序＝uint16 升序、4 位小写 hex、逗号分隔（ja4.go:428-430、529-538）。签名算法不排序、以 `_` 连接：dts:190 `The signature algorithm hex values are then added to the end of the list in the order that they appear (not sorted) with an underscore delimiting the two lists.`；空则 dts:214 `If there are no signature algorithms in the hello packet, then the string ends without an underscore and is hashed.`（`ja4.go:432-440`）；签名算法也跳 GREASE（JA4.md:231-235，注明 pin 才改）。

**ALPN 位**
- dts:159 `The first and last characters of the ALPN (Application-Layer Protocol Negotiation) first value.` / dts:168 `If there are no ALPN values or no ALPN extension then we print “00” as the value in the fingerprint.`
- JA4.md:118-119：`If there is no ALPN extension, no ALPN values, or the first ALPN value is empty, then we print "00" as the value in the fingerprint.`
- 现规则（tls.go:370-424；CHANGELOG.md:1294-1303、1227-1230）：无扩展/无值/首值为空→`00`；否则取首值首末字节，`0x20-0x7E` 写自身，**端字节 ≥0x80 写 `9`**（`68 ff→h9`、`ff 68→9h`），**端字节 <0x20 或 0x7F→整体 `99`**，**单字节可打印值写两遍**（`2d→--`、`68→hh`）。上游自注此裁定与其 Rust/Wireshark 参考不同（JA4.md:146-149、158-159），并称文本规范与语料向量之间存在无法同时满足的矛盾（JA4.md:176-184）。

**两个 hash**
- dts:112-122：`(sha256 hash of the list of cipher hex codes sorted in hex order, truncated to 12 characters) _ (sha256 hash of (the list of extension hex codes sorted in hex order)_(the list of signature algorithms), truncated to 12 characters)`；dts:171 `A 12 character truncated sha256 hash of the list of ciphers sorted in hex order, first 12 characters. The list is created using the 4 character hex values of the ciphers, lower case, comma delimited, ignoring GREASE.`
- 代码 `internal/parser/hash.go:13-37`：`hex(sha256(in))[:12]`；空输入→哨兵 `EmptyHash = "000000000000"`（非空串的 SHA256）。`TruncatedHashNoSentinel` 只服务 JA4H part b / JA4X。cipher hash `ja4.go:399-408`，extension hash `ja4.go:444-446`。
- 示例基准 `t13d1516h2_8daaf6152771_e5627efa2ab1`（dts:241）。**JA4.md:241-248 自行说明图像那串 `t13d1516h2_acb858a92679_e5627efa2ab1` 混用两种渲染、无实现会产出。**
- 派生形式：`JA4_r` `ja4.go:316-348`；`JA4_o` 保序且**保留** SNI/ALPN `ja4.go:459-470`、`493-503`（dts:245 `The "o" option includes the original values in the original order, less GREASE values. This means SNI (0000) and ALPN (0010) are included.`）；`JA4_ro` `ja4.go:472-478`。四字段落 `Fingerprint/Raw/OriginalOrder/RawOriginalOrder`（ja4.go:214-225）。`JA4_o` 哨兵读**排序串**是否为空，上游注明选择跟 Python、与其 Rust 参考在极端输入不同（ja4.go:480-503）。

## 4 QUIC

支持：README.md:43-46 解密 QUIC Initial（RFC 9001/9369）读内层 hello；`ja4.go:128-197` 按 **DCID hex** 累积 CRYPTO 帧（`DecryptQUICInitialCrypto`→`CollectCryptoFragments`→`ClientHelloFromCryptoFragments`，`internal/parser/quic.go`）。状态界：1000 连接 / 30s 老化 / 每连接 16384 字节（`ja4.go:14-34`、CHANGELOG.md:1147-1149）；隧道按内层地址对分组并建 reported-key 索引（ja4.go:155-165、42-50、275-292）。
近期 QUIC 修复：PING 帧挡在 CRYPTO 前曾使整条 hello 读不到（CHANGELOG.md:918-921）；片段缺失时不再解析半条消息（1144-1146）；QUIC 分支改读内层 UDP（1122-1127）；值迁移 `q12i030000_55b375c5d22e_000000000000`→`q13d0310h3_55b375c5d22e_cd85d2d88918`（1133-1141）。
自陈未解：README.md:567 —— hello 大到跨多个 Initial 时 CRYPTO 重组可能还原不出完整握手，扩展计数与 hash 会与其 Python 参考略有差异，TCP 路径不受影响。JA4L 的 QUIC 侧：合并数据报只读第一个包、point C fall-through、point B 未裁定（CHANGELOG.md:104-112、134-142），`ssh2.pcapng/33/JA4L-S` 与 `tls3.pcapng/25/JA4L-S` 未登记使 `make conformance` 现 exit 2（README.md:557-562）。不读 HTTP/3（QPACK 在其不解密的受保护包里；#164 于 08-16 无代码关闭，README.md:47-50、CHANGELOG.md:48-56）。v1.3.x 的重组修复属 **TCP**（界：16395 字节/64 段/1000 连接/30s/FIN·RST 清向，`docs/methods/ja4.md:62-75`）。
