# 09 · 与现有指纹库的对齐与超越

本文回答两件事：**① 我们和 curl_cffi / curl-impersonate / tls_client / cycletls / uls /
gospider / pyhttpx / requests_go 这些库的关系是什么；② 我们靠什么比它们更强。**

一句话：**它们交付"一份固定的指纹清单"，我们交付"一套可验证、可推导、会随浏览器演化
自动扩展的指纹模型"。** 清单是结果，模型是能力。

---

## 1. 先对齐：该有的必须都有

| 维度 | 典型指纹库 | 我们 |
|---|---|---|
| 主流浏览器 | Chrome / Firefox / Safari / Edge 的若干版本 | ✅ 同一批族的**更多版本与平台**（含 macOS/Windows/Android/iOS） |
| 覆盖方式 | 手工维护的固定清单，等库更新 | ✅ **自测锚点 + 谱系内插**，窗口内任意版本可生成（§3） |
| 非浏览器客户端 | 少数（curl / okhttp / IE 等，视库而定） | ✅ curl / okhttp / IE / PowerShell / Postman / 代理工具（Charles / Fiddler / Reqable） |
| 移动 App 浏览器 | 基本没有 | ✅ 微信 / UC / QQ / MQQ / 夸克 / 小米 / 华为 / vivo / 三星 / 百度 / 荣耀 / 魅族 等 |
| 建模层次 | 多数只做 TLS（部分带 H2 / 请求头） | ✅ TLS + HTTP/2 + **HTTP/3（QUIC）** + HTTP/1.1 + TCP + 身份头 + 行为节 |
| 语言/形态 | 各自绑定（C 补丁 / Go / Python 封装） | ✅ 原生 Go 库（`core`）+ Python/Node **自检通道**（crosslang） |

> 覆盖数字是**事实陈述**（`core/profiles/builtin` 可数）；对方的确切清单随其版本变化，
> 本文不逐版本核对，只按能力类别对比。

**当前库存**：`自测 29 + 谱系内插 14 + 外部导入 319 = 362 个预设`（族数 29）。

---

## 2. 分级：我们敢说"哪一条能信、信到什么程度"

这是所有对手都**没有**的机制——它们只会给你一份清单，不告诉你哪条是靠得住的。

| `grade` | 含义 | 能不能参与 E1 级断言 |
|---|---|---|
| 留空 | **本项目自测**（E1 真机抓包 / E1r 字段级实测 / E2 本机可复现） | ✅ 可以 |
| `E2i` | **谱系内插**：由实测锚点 + 逐字段稳定性规则推导；区间内所有比较字段都稳定 | ❌ 不参与（未实测该版本） |
| `E2i-u` | 同上，但区间内有字段变化且**边界未知** | ❌ 不参与 |
| `E3` | **外部指纹集导入**（补覆盖面对齐；不做保真承诺） | ❌ 不参与 |

守门：`core/profiles/provenance_test.go`（等级与来源必须自洽）+ 4 个 E1 测试一律跳过
`grade != ""`（`fp_oracle` / Chromium GT / Firefox GT / TLS1.2 回退）。

**升级路径**（E3 → E2i/E1）：想提高某条的可信度，唯一的办法是**采锚点**：

```
自测锚点（真机抓包） ⇒ gen-profiles 生成 grade=""（可参与 E1 断言）
锚点之间的版本      ⇒ -lineage 内插（E2i / E2i-u，明确标注未定界字段）
外部导入            ⇒ E3（只补覆盖，等锚点来升级）
```

## 3. 超越之一：谱系——把"抄一份 JSON"换成"描述演化"

`tests/e2e/cmd/gen-profiles -lineage`（代码 `lineage.go`，测试 `lineage_test.go`）：

1. **逐字段稳定性判定**：对我们自己的实测锚点做跨版本比较，回答"这个字段在哪个版本变过"；
2. **内插**：锚点窗口内的缺失版本按"≤ 目标版本的最高锚点"取骨架（step 语义），
   **identity 按目标版本重算**（UA 与 UA-CH 必须带该版本号，否则一眼假）；
3. **拒绝**：窗口外一律不外推；区间内**密码套件**变过时拒绝内插——那不叫推导，叫凭空造栈；
4. **逐字段标注**：每个字段的来源是 `stable-in-window` 还是 `unbounded@143-152`，写进
   `profiles/evidence/lineage.json`。

跑出来的实际结果（2026-09-28）：

| 族 | 锚点 | 稳定字段 | 内插 | 结论 |
|---|---|---|---|---|
| chrome | 137,141,142,143,152 | 17/21 | 138,139,140（**E2i**）、144–151（E2i-u） | 143→152 之间 `sig_algs`、扩展集合、`51764` 变过（边界未知） |
| firefox | 140,144 | 21/21 | 141,142,143（**E2i**） | 全字段稳定 ⇒ 高可信内插 |
| safari | 18,26 | 14/21 | **拒绝 19–25** | ciphers/groups/key_shares/versions/padding 都变过 ⇒ 需锚点 |

**它同时是一份"浏览器指纹演化日志"**（全部来自我们自己的实测）：

- **Chrome 143→152**：`51764` 出现；`sig_algs` 增加 GREASE 与 `0x0904/0x0905/0x0906`
  （**ML-DSA 后量子签名**）⇒ 这正是 G12 记录的那条缺口，现在有了实测锚点定位；
- **Safari 18→26**：密码套件序变化、`supported_versions` 丢掉 1.1/1.0、
  groups/key_shares 增加 `0x11ec`（**X25519MLKEM768** 混合组）、padding 消失。

**为什么这比"固定清单"强**：浏览器发新版时，对手要等库更新；我们只需**再采一个锚点**，
一条命令就把窗口内的版本补齐，并自动告诉用户哪些字段可信、哪些还缺锚点。

## 4. 超越之二：状态与场景，而不是"一条静态指纹"

| 机制 | 我们 | 对手 |
|---|---|---|
| Firefox 会话形态 | 首访（35+45）/ 复访（45+41）/ **无痕**（三者皆无）三形态建模 | 一条静态指纹 |
| TLS 1.3 会话复用 | `pre_shared_key` 占位 + 票据缓存 + **丢票回退**（对端不吃 binder 时自动重试）；老客户端（无 1.3）**不发** 41（否则结构非法） | 多数不管，或直接崩 |
| ECH | 逐连接 GREASE（不是固化字面量）+ 真 ECH 通道 | 少见 |
| 扩展洗牌 | Chromium 逐连接洗牌（GREASE/padding/PSK 位置固定） | 少见 |
| 泛化 GREASE 扩展 | `51764` 子项顺序按数据判定并钉住 | 无 |
| HEADERS 内嵌 priority | 分族实测（Chrome `excl=1/w=256`、Firefox `excl=0/w=42`） | 基本没有 |
| 身份层 | TLS/UA/UA-CH/头顺序/H2/H3 **同源一致**（同一个 profile 描述） | 各层分散配置，容易互相矛盾 |

## 5. 超越之三：可验证性——我们敢让人验

三层验证，全部入库、可复跑：

1. **独立解析器 oracle**（`tests/e2e/fp_oracle_test.go`）：本地起一个不依赖 uTLS 的
   ClientHello 解析端，对我们发出去的字节逐字段断言（SETTINGS/流控/priority/头顺序/…）；
2. **wire 级抓包**（`h2_capture_test.go`）：真握手 + 真帧解析，验证 H2 首帧形态；
3. **跨语言自检**（`crosslang`）：同一预设经 Go/Python/Node 发出，JA3/JA4 必须一致；
4. **守门**：预设只能由标本生成（`gen-profiles`）；谱系内插有独立一致性测试
   （骨架保真 / 不外推 / 骨架变化拒绝 / 产物可编译且等级正确）。

对手基本只保证"能连上"，不保证"和真浏览器逐字段一致"，也不提供让你自证的接口。

## 6. 与对手的兼容（下一步）

- **导出互操作**：把我们的 profile 导出成对方能吃的格式（JA3/JA4R 串、curl-impersonate
  的 `--impersonate` 目标名之外的原始 CH、tls-client 的 JSON），让"对齐"不止是覆盖面对齐；
- **锚点采集一条龙**：`cmd/e1-browser` + `-lineage` 串成一条命令（采到新版本 ⇒ 生成 ⇒ 内插 ⇒ 跑回归）；
- **锚点补齐清单**：Safari 19/20/22/24、Chrome 147/150（缩小 `E2i-u` 的边界）。

---

## 7. 结论

- **对齐**：覆盖面上不输（浏览器四族 + 工具客户端 + App 浏览器，29 族 / 362 预设），
  层次上更多（TLS/H2/H3/TCP/身份）。
- **超越**：我们把"清单"变成"模型"——证据分级、谱系内插、逐字段可信度、拒绝外推、
  状态与场景建模、三层自验证。
- **一句话边界**：**没实测的绝不说成实测的**（`grade` 就是这条线的载体）；
  想让它更可信，就给锚点，而不是改 label。
