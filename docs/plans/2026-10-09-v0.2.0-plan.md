## P1 — pcap 直导入（core 核 → FFI → 三语言）

### T1.1 解析核入 core（`core/pcapimport`，新包）

- 把 `core/cmd/geektls/importpcap.go` 的解析核整体搬进新包（CLI 只留参数解析与输出壳）：
  - `pcapimport.Import(data []byte, opts Options) (*Result, error)`
    —— `Result{Records []*Record; Skipped []string}`；
    文件读取留在调用方（CLI / FFI 各自读文件；Go 绑定提供 path 与 bytes 两个入口）。
  - `Record / TCPInfo / HTTP2Info` 的 JSON tag 与 CLI 现输出**逐字段一致** ⇒ CLI 输出字节不变。
  - 记录组装（kind=e1p_pcap / grade=E1p / source=pcap:<base>#<n> / tcp 节 / ja3/ja4 / UA）随核下沉。
- CLI `import-pcap` 行为与输出**零变化**：`importpcap_test.go` 原样保留作 CLI 回归。
- 新包测试：pcap classic + pcapng 两容器、CH 跨 3 段乱序重组、SYN 选项/TTL/窗口/DF 导出、
  四类拒绝（resumption / 缺 SYN / 抓包缺口 / 无 CH）、tcp-only 与 all。
- **判据**：CLI 全部旧测试不改一行、全绿；新包测试覆盖上述场景。

### T1.2 FFI `gtls_import_pcap`（加性第 24 个导出；ABI=1 不动）

- 输入 JSON：`{"path"|"data_b64", "name"?, "source_base"?, "ua"?, "stream"?, "all"?, "tcp_only"?}`
  （`path` 优先，`data_b64` 兜底——进程内直接吃字节）。
- 输出 JSON：`{"records":[...], "skipped":["<流> → <原因>", ...]}`。
- `geektls.h` 同步声明；`CONTRACT-FREEZE.md` #3 计数 23→24（**只增不改**，属允许动作）。

- 测试：`tests/e2e/python/test_import_pcap.py`（**测试内合成 pcap 字节**；断言
  records/skipped/clienthello_hex/JA4/tcp 节）。

### T1.4 Node 绑定 `geektls.importPcap(...)` + e2e 测试

- 测试：`tests/e2e/node/import_pcap.test.js`（与 Python 同合成器口径、同断言面）。

### T1.5 Go 绑定 `geektls.ImportPcap / ImportPcapBytes` + 测试

### T1.6 测试数据：**测试内合成 pcap 字节**（原计划落 fixture 文件，执行时改为更自包含的测试内合成）
